# 龙珠超次元乱战（DBM）漫画下载与修复总结

> 日期：2026-09-30 ~ 10-01 · 脚本：`/private/var/folders/.../T/opencode/dbm_download.py`（下载）、`dbm_fix.py`（修复）

## 一、任务背景

用 Python 脚本从 [dragonball-multiverse.com](https://www.dragonball-multiverse.com) 下载《龙珠：超次元乱战》中文版全部 **116 话**，按话存图（`第NNN话_标题/NNNN.jpg`），不打包 CBZ。最终落盘 `~/Downloads/龙珠超次元乱战/`，**116 话 / 2759 张 / 740 MB**。

## 二、遇到的问题与解决

### 1. 断点续下与重试

- 脚本原生支持续传（已存在且非空的 jpg 跳过）；`fetch()` 重试从 3 次加到 **8 次 + 指数退避（1s→2s→…→30s）**，扛住站点 SSL 抖动
- 使用参数：`python3 dbm_download.py --no-cbz`（不加 `--no-cbz` 会自动打包 CBZ，本任务不需要）

### 2. 站点改版导致下载污染（核心问题）

**现象**：部分话整话下成 Instagram 图标等垃圾图。

**根因**：站点正逐页从旧格式迁移到新格式——

| | 旧格式（大部分页） | 新格式（部分页） |
| --- | --- | --- |
| 漫画图 | `<img>` 直出**带中文对白的成品图** | CSS `background-image` 放**无字原画**（`lg=ono`） |
| 对白 | 烧在图里 | HTML `<div class="balloon">` 文字层叠加 |

老脚本正则在新页面匹配不到背景图，错误抓取页面上第一张 `<img>`（社交图标）。

**受影响范围**：扫描全库，锁定 **100 张污染页，涉及 19 话**（93 话 19 张、108/116 话各全话 24 张等）。

### 3. 修复方案演进

1. ❌ PIL 模拟官网排版（ono 原画 + balloon 文字叠加）——字号/字体还原不准
2. ✅ **headless Edge 渲染官网页面 + 裁剪漫画区**（最终采用）——文字是官方原样渲染
   - 边框定位：贯穿画面的**长黑竖线对**（间距 = 漫画宽+2）+ 顶部横线配对（排除页面底部 40 行厚黑块误配）
   - 验收：**模板比对**（裁剪结果 vs ono 原画，灰度 diff < 35 为通过）——像素质检无法发现的"裁到错误内容"靠它抓出 16 页
   - 重试：Edge 无头截图时机不稳（页面未渲染完就截图），失败自动重截
3. 特殊页单独处理：
   - **page-2167**（多层动画页）：加 `--virtual-time-budget` 等动画播完；发现右上角混入 "↺ Replay" 按钮，用 Vision OCR 定位 + 相邻画面镜像修补移除
   - **page-2379**：同理渲染裁剪
   - 横版大图（page-8: 1200×848、page-2186: 1000×700）：无对白页，直接下 ono 原画即成品；截图窗口宽度需 `max(900, w+100)`

### 4. 质检体系（层层递进，教训：像素质检抓不到"内容错误"）

| 检查 | 抓到的问题 |
| --- | --- |
| 尺寸/图标过滤 | 初期 100 张污染页 |
| 蓝背景（官网渐变蓝 #2d72ea 系）边缘/块扫描 | 裁剪越界、页面未加载完的半蓝图 |
| 黑边框完整性 | 边框缺失的偏移裁剪 |
| **模板比对**（ono 原画 vs 成品） | 16 张"尺寸完美但内容错误"的顽固坏页 |
| **Vision OCR** | Replay 按钮（用户肉眼发现后纳入体系） |

### 5. 最终全库验收（四项全过）

- ✅ 2759 张全部可解码（发现并修复 1 张截断文件：第 41 话 0916.jpg）
- ✅ 无图标/小图残留
- ✅ 100 张修复页 OCR 扫描无网页 UI 残留（3 张命中 "not for profit" 经与 ono 比对确认是漫画自带署名）
- ✅ 116 话页数与站点 chapters.html 一致（1000/2000/2312 三页为站点纪念页/悼念页，本无漫画画布）

## 四、整理打包（2026-10-01，~/Desktop 版）

对 `~/Desktop/龙珠超次元乱战`（115 话 / 2735 张 / 732 MB）完成「改名 → 重排 → AVIF → CBZ」全流程：

| 步骤 | 命令 | 结果 |
| --- | --- | --- |
| 目录改名 | 一次性脚本（`第NNN话_Chapter N_ 标题` → `NNN 标题`） | 115/115 |
| 页码重排 | `chapter-pages-rename-by-order` | `0000.jpg` → `00.jpg`（⚠️ 全局页码不可恢复，`dbm-fix --replace` 从此无法定位） |
| 转 AVIF | 逐章 `convert-image-format-to avif`（**只处理最外层，需循环**；`hentai-polish` 可递归一步到位但命名不同） | 2735 张，732M → 246M |
| 打包 | `zip-all` + 后缀改 `.cbz`（`zip_all.py` 只产 `.zip`） | 115 个，包内保留章节目录层 |

**按图片标题修正的章节名**（Vision OCR 首页提取 + 裁图人工确认）：

- `114 Universe 5 - XXI_ The Story` → `114 第5宇宙 XXI：前尘往事`
- `115 XXI’s army gains in strength!` → `115 XXI 大军战力暴增！`
- `110 …1/5★…` → `110 第7宇宙 ★☆☆☆☆ 你失去一位客户了 😠👎`（`1/5★` 是五星评分图形，非分数）
- `090 最后一场1_4决赛` → `090 最后一场四分之一决赛`（文件名里 `/` 非法，`clean()` 机械替换成 `_` 所致）

OCR 提题结论：仅适合**个别英文标题章**人工确认后改，全量自动重命名不可行（112/115 命中且混入装饰文字、话号识别错）。002/003/004 前几页是汉化组封面页，无标题可提。

**脚本修复**（`manga/src/`）：

- `dbm_download.py`：① 标题加 `html.unescape`（`I'k'l` 曾被写成 `I&#039;k&#039;l`）；② 目录名改 `NNN 标题` 格式；③ `clean()` 分数转汉字（`1/4`→四分之一、`N/10`→十分之N、其余 `A／B` 全角斜线）
- `dbm_fix.py`：`target_path()` 由 `glob("第*话*")` 改为遍历子目录，新旧目录名格式通吃

## 五、关键经验

- 站点反爬/改版下，**"渲染截图 + 官方素材模板比对"** 是比纯像素分析可靠得多的验收方式
- 用户肉眼抽查（grid 缩略图总览）多次发现自动化质检的漏网之鱼——缩略图总览 sheet 是高效的验收工具
- macOS 自带能力很好用：**Vision 框架 OCR**（定位 UI 文字残留）、**sips**（图片转换）、headless Edge（`--screenshot` / `--virtual-time-budget` / `--dump-dom`）
- 改 cbz 里的目录名必须**重建压缩包**（zip 条目路径是元数据，改文件名动不到它）
- 批量改名前先跑官网 `image.php`/`page-N.html` 探测，能区分"漏下"和"站点本就无图"（page-9/21 官网返回 292 字节 Error SVG，本无图）
